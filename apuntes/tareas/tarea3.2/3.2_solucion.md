# **Solución 3.2: Creación de usuarios y grupos**

### **Descripción de la tarea**

En esta práctica realizaremos la creación de diferentes usuarios y grupos y haremos uso de los principales comandos de Linux para su administración.

Salvo que se indique otra cosa, todos los usuarios tendrán su carpeta personal en `/home`, la shell `/bin/bash` y la contraseña `abc123.`.

### **Pasos de la tarea**

1. Crear los grupos sistemas, informatica y micro.
2. Crear el usuario1 con grupo principal informatica y sin shell, de modo que no pueda iniciar sesión.
3. Crear el usuario2 con una cuenta que caduque mañana. La fecha de mañana se debe calcular con el comando `date`, sin escribirla a mano.
4. Crear el usuario3 y hacer que en el primer inicio de sesión se le pida el cambio de contraseña. Al entrar con el usuario3, la nueva contraseña será, por ejemplo: `Password,319`.
5. Crear el usuario4 y, una vez creado, hacer que su cuenta caduque el 30/06/2027.
6. Crear el usuario5. Tiene que tener el alias de comando `listar`, que debe ser un `ls` con formato largo que ordene los ficheros por fecha de modificación. Además, tiene instalado Java en el directorio `/usr/local/jdk1.7` y tiene que tener definida la variable `JAVA_HOME`. Ambas cosas deben estar disponibles cada vez que el usuario inicie sesión. La instalación de Java se simulará creando ese directorio vacío.
7. Comprobar el correcto funcionamiento del usuario5.
8. Eliminar los usuarios y grupos creados.

## Solución

En el sistema ya existe el usuario `usuario` (UID y GID 1001), así que los nuevos usuarios y grupos reciben los números siguientes.

> **Nota:** Todos los usuarios se crean con la opción `-p "$(mkpasswd 'abc123.')"`. `mkpasswd` está en el paquete `whois`. Si no está instalado, `$(mkpasswd ...)` queda vacío y el usuario se crea sin una contraseña válida. Se instala con `apt install whois`.

### 1. Crear los grupos

```bash
root@debian:~# groupadd sistemas && groupadd informatica && groupadd micro
root@debian:~# tail -n3 /etc/group
sistemas:x:1002:
informatica:x:1003:
micro:x:1004:
```

### 2. Usuario1: grupo principal informatica y sin shell

`-g` indica el grupo principal. Como se lo damos nosotros, `useradd` no crea el grupo privado `usuario1`. La shell `/usr/sbin/nologin` impide iniciar sesión.

```bash
root@debian:~# useradd -m -g informatica -s /usr/sbin/nologin -p "$(mkpasswd 'abc123.')" usuario1
root@debian:~# tail -n1 /etc/passwd
usuario1:x:1002:1003::/home/usuario1:/usr/sbin/nologin
```

Comprobamos que no puede entrar:

```bash
root@debian:~# su - usuario1
```

En lugar de abrir una shell, `nologin` muestra un mensaje que indica que la cuenta no está disponible, y la sesión termina.

### 3. Usuario2: la cuenta caduca mañana

`-e` indica la fecha de caducidad de la cuenta en formato `AAAA-MM-DD`. Para no escribirla a mano, la calculamos con `date`:

```bash
root@debian:~# date -d tomorrow +%F
2026-11-04
root@debian:~# useradd -m -s /bin/bash -p "$(mkpasswd 'abc123.')" -e "$(date -d tomorrow +%F)" usuario2
root@debian:~# tail -n1 /etc/passwd
usuario2:x:1003:1005::/home/usuario2:/bin/bash
root@debian:~# chage -l usuario2 | grep "cuenta caduca"
La cuenta caduca                                                : nov 04, 2026
```

La fecha que aparezca dependerá del día en que se haga la práctica. Este usuario sí tiene grupo privado, `usuario2`, y recibe el GID 1005, porque el 1003 y el 1004 ya están ocupados por `informatica` y `micro`.

> **Nota:** La fecha de caducidad es el día **a partir del cual** la cuenta queda bloqueada. Con la orden anterior, el usuario2 puede iniciar sesión hoy, pero ya no podrá hacerlo mañana.

### 4. Usuario3: cambio de contraseña en el primer inicio de sesión

```bash
root@debian:~# useradd -m -s /bin/bash -p "$(mkpasswd 'abc123.')" usuario3
root@debian:~# tail -n1 /etc/passwd
usuario3:x:1004:1006::/home/usuario3:/bin/bash
root@debian:~# passwd -e usuario3
root@debian:~# chage -l usuario3 | head -n1
Último cambio de contraseña                                     : se debe cambiar la contraseña
```

`passwd -e` (*expire*) marca la contraseña como caducada: la fecha de su último cambio pasa a ser `0` en `/etc/shadow`, y el sistema obliga a cambiarla en el siguiente inicio de sesión.

> **Nota:** Se obtiene el mismo resultado con `chage -d 0 usuario3`.

Para comprobarlo hay que iniciar sesión **desde un usuario normal** o en una consola, no desde `root`: cuando `root` usa `su`, no se le pide la contraseña del otro usuario.

```bash
usuario@debian:~$ su - usuario3
```

`su` pide la contraseña actual (`abc123.`) y a continuación avisa de que hay que cambiarla. Pide otra vez la contraseña actual y después la nueva, `Password,319`, dos veces. A partir de ese momento, el usuario3 entra con la nueva contraseña.

### 5. Usuario4: la cuenta caduca el 30/06/2027

Esta vez creamos primero el usuario y después le ponemos la caducidad con `chage -E`:

```bash
root@debian:~# useradd -m -s /bin/bash -p "$(mkpasswd 'abc123.')" usuario4
root@debian:~# chage -E 2027-06-30 usuario4
root@debian:~# chage -l usuario4
Último cambio de contraseña                                     : nov 03, 2026
La contraseña caduca                                    : nunca
Contraseña inactiva                                     : nunca
La cuenta caduca                                                : jun 30, 2027
Número de días mínimo entre cambio de contraseña                : 0
Número de días máximo entre cambio de contraseña                : 99999
Número de días de aviso antes de que caduque la contraseña      : 7
```

> **Nota:** `usermod -e 2027-06-30 usuario4` hace lo mismo. Para quitar la caducidad, se usa `chage -E -1 usuario4`.

### 6. Usuario5: alias `listar` y variable `JAVA_HOME`

Creamos el usuario y simulamos la instalación de Java creando su directorio:

```bash
root@debian:~# useradd -m -s /bin/bash -p "$(mkpasswd 'abc123.')" usuario5
root@debian:~# tail -n1 /etc/passwd
usuario5:x:1006:1008::/home/usuario5:/bin/bash
root@debian:~# mkdir -p /usr/local/jdk1.7
```

Añadimos el alias a `~/.bashrc` y la variable a `~/.profile`:

```bash
root@debian:~# echo "alias listar='ls -lt'" >> /home/usuario5/.bashrc
root@debian:~# echo 'export JAVA_HOME=/usr/local/jdk1.7' >> /home/usuario5/.profile
```

- **El alias va en `~/.bashrc`**, porque Bash lee ese fichero en cada shell interactiva. `-l` es el formato largo y `-t` ordena por fecha de modificación, con los más recientes primero. Si se añade `-r` (`ls -ltr`), el orden se invierte y el fichero modificado más recientemente queda al final.
- **La variable va en `~/.profile`**, porque Bash lo lee al iniciar sesión. Se escribe con `export` para que la reciban también los programas que lance el usuario. Sin `export`, sería una variable de la shell y un programa Java no la vería.

Los dos ficheros los copió `useradd -m` desde `/etc/skel` y pertenecen a `usuario5`. Al añadirles líneas con `>>`, siguen siendo suyos.

> **Advertencia:** No hay que crear un fichero `~/.bash_profile`. Si existe, Bash lo lee al iniciar sesión **en lugar de** `~/.profile`, y en Debian es `~/.profile` el que carga `~/.bashrc`. Con un `~/.bash_profile` creado a mano, el alias dejaría de estar disponible en las sesiones de login.

> **Nota:** En una instalación real de Java se suele añadir también su directorio `bin` al `PATH`, para poder ejecutar `java` sin escribir la ruta completa: `export PATH="$JAVA_HOME/bin:$PATH"`.

### 7. Comprobar el funcionamiento del usuario5

`su -` abre una sesión de login, igual que al entrar por consola o por SSH, así que se leen `~/.profile` y, desde él, `~/.bashrc`:

```bash
root@debian:~# su - usuario5
usuario5@debian:~$ alias listar
alias listar='ls -lt'
usuario5@debian:~$ echo $JAVA_HOME
/usr/local/jdk1.7
usuario5@debian:~$ env | grep JAVA_HOME
JAVA_HOME=/usr/local/jdk1.7
usuario5@debian:~$ touch fichero1
usuario5@debian:~$ touch fichero2
usuario5@debian:~$ listar
total 0
-rw-r--r-- 1 usuario5 usuario5 0 nov  3 10:15 fichero2
-rw-r--r-- 1 usuario5 usuario5 0 nov  3 10:14 fichero1
usuario5@debian:~$ exit
```

- **`env | grep JAVA_HOME`** confirma que la variable se ha exportado. Sin `export`, `echo` la mostraría, pero `env` no.
- **`listar`** muestra primero `fichero2`, el modificado más recientemente.
- **Si los dos ficheros se crean en el mismo minuto**, la hora que muestra `ls` coincide, pero el orden sigue siendo correcto, porque `ls` compara la hora exacta.

> **Nota:** El alias hay que probarlo en una shell interactiva, como arriba. Con `su - usuario5 -c 'listar'` no funcionaría, porque las shells no interactivas no leen `~/.bashrc` ni expanden alias.

### 8. Eliminar los usuarios y grupos creados

`userdel -r` borra cada usuario junto con su directorio personal y su grupo privado. La salida de errores se descarta porque `userdel` avisa de que no encuentra el buzón de correo de cada usuario, que nunca se llegó a crear.

```bash
root@debian:~# for i in $(seq 1 5); do userdel -r usuario${i} &> /dev/null; done
root@debian:~# grep -c '^usuario[1-5]:' /etc/passwd
0
```

Después borramos los grupos y el directorio de Java. `informatica` solo se puede borrar después de borrar el usuario1, porque era su grupo principal.

```bash
root@debian:~# groupdel sistemas
root@debian:~# groupdel informatica
root@debian:~# groupdel micro
root@debian:~# rmdir /usr/local/jdk1.7
root@debian:~# grep -cE '^(sistemas|informatica|micro|usuario[1-5]):' /etc/group
0
```
