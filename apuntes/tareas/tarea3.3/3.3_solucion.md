# **Solución 3.3: Uso de loginctl para el monitoreo de sesiones y usuarios conectados al sistema**

### **Descripción de la tarea**

En esta práctica vamos a supervisar las sesiones que los usuarios `usuario` y `operador` tienen abiertas en una máquina Debian 13, y a cerrarlas desde el administrador con `loginctl`.

Los dos usuarios se conectarán por SSH desde otra máquina de la red. Todas las órdenes de supervisión se ejecutan como `root` en la máquina Debian.

### **Pasos de la tarea**

0. Preparar el escenario: instalar el servidor SSH en la máquina Debian y crear el usuario `operador`, con la shell `/bin/bash` y la contraseña `abc123.`.
1. Los usuarios `usuario` y `operador` se conectarán al sistema por SSH: `usuario` abrirá una conexión y `operador` abrirá **dos**. Mostrar las sesiones existentes en el servidor.
2. A continuación, el usuario `operador` va a editar el fichero `fichero.txt` en una de sus conexiones. ¿Cómo podemos ver lo que está haciendo ese usuario en un momento concreto?
3. Ahora queremos ver los datos de esa sesión del usuario: desde qué IP se ha conectado, cuánto tiempo lleva conectado, el tipo de servicio por el que se ha conectado y el tiempo que lleva sin escribir.
4. A continuación queremos cerrar las dos conexiones de `operador`:
   - Una la terminaremos de forma **ordenada**: se cerrarán todos los programas del usuario de forma ordenada y se le echará del servidor, cerrándole la conexión.
   - La otra la terminaremos de forma **fulminante**: se cerrarán todos los programas del usuario de forma inmediata, sin darles opción a terminar ordenadamente, y se le echará del servidor, cerrándole la conexión.
5. Mostrar cuántas sesiones existen en este momento en el sistema. Cuando se compruebe que el usuario `operador` ya no está conectado, bloquearlo y cambiar su shell a `/usr/sbin/nologin`.

## Solución

En la solución, la máquina Debian tiene la IP `192.168.100.20` y los usuarios se conectan desde otra máquina de la red, la `192.168.100.10`. Los números de sesión, los PID, las fechas y las horas cambiarán en cada equipo.

### 0. Preparar el escenario

Instalamos el servidor SSH y creamos el usuario `operador`:

```bash
root@debian:~# apt install openssh-server
root@debian:~# useradd -m -s /bin/bash -p "$(mkpasswd 'abc123.')" operador
root@debian:~# getent passwd operador
operador:x:1001:1001::/home/operador:/bin/bash
```

> **Nota:** `mkpasswd` está en el paquete `whois`. Si no está instalado, `$(mkpasswd ...)` queda vacío y el usuario se crea sin una contraseña válida. Se instala con `apt install whois`.

### 1. Conectar los usuarios y mostrar las sesiones

Desde la otra máquina abrimos tres terminales: en una se conecta `usuario` y en las otras dos, `operador`:

```bash
ssh usuario@192.168.100.20      # terminal 1
ssh operador@192.168.100.20     # terminal 2
ssh operador@192.168.100.20     # terminal 3
```

En la máquina Debian listamos las sesiones:

```bash
root@debian:~# loginctl list-sessions
SESSION  UID USER     SEAT LEADER CLASS   TTY   IDLE SINCE
     14 1000 usuario  -    1102   user    pts/0 no   -
     15 1000 usuario  -    1108   manager -     no   -
     19 1001 operador -    4403   user    pts/1 no   -
     20 1001 operador -    4410   manager -     no   -
     21 1001 operador -    4520   user    pts/2 no   -

5 sessions listed.
```

Hay tres conexiones, pero el listado muestra cinco sesiones:

| Clase | Qué es |
|---|---|
| `user` | Una sesión de inicio de sesión real: cada una de las conexiones SSH. Las sesiones de `operador` son la 19 y la 21. |
| `manager` | La sesión que `systemd` abre internamente para el gestor de servicios de cada usuario (`user@.service`) cuando ese usuario entra por primera vez. Solo hay una por usuario, aunque tenga varias conexiones. |

> **Nota:** Por eso el número de sesiones del listado no coincide con el de conexiones. Para contar solo las conexiones hay que fijarse en las sesiones de clase `user`. Si solo nos interesan los usuarios conectados, `loginctl list-users` muestra uno por línea.

### 2. Ver qué está haciendo el usuario

En la terminal 2, `operador` abre el fichero con `nano fichero.txt`. Para ver qué está haciendo, consultamos el estado de su sesión, la 19:

```bash
root@debian:~# loginctl session-status 19
19 - operador (1001)
           Since: mar 2026-11-03 10:15:02 CET; 3min 43s ago
           State: active
          Leader: 4403 (sshd-session)
             TTY: pts/1
          Remote: 192.168.100.10
         Service: sshd; type tty; class user
            Unit: session-19.scope
                  ├─4403 "sshd-session: operador [priv]"
                  ├─4434 "sshd-session: operador@pts/1"
                  ├─4435 -bash
                  └─4725 nano fichero.txt
```

El apartado `Unit` muestra el árbol de procesos de la sesión: la conexión SSH, la shell de `operador` y, colgando de ella, el `nano fichero.txt` que está usando en este momento.

> **Nota:** En Debian 13, OpenSSH atiende cada conexión con un proceso propio llamado `sshd-session`. En versiones anteriores, esos procesos aparecían como `sshd`.

Otras formas de verlo:

- **Todas las sesiones de un usuario:** `loginctl user-status operador` muestra el árbol de procesos de todas sus sesiones a la vez.
- **Con `w`:** muestra en la columna `WHAT` la orden que está ejecutando cada conexión:

```bash
root@debian:~# w operador
 10:18:45 up  1:02,  3 users,  load average: 0,00, 0,00, 0,00
USER     TTY      FROM             LOGIN@   IDLE   JCPU   PCPU  WHAT
operador pts/1    192.168.100.10   10:15    1:12   0.05s  0.02s nano fichero.txt
operador pts/2    192.168.100.10   10:16    2:30   0.01s  0.01s -bash
```

### 3. Ver los datos de la sesión

`loginctl show-session` muestra todas las propiedades de una sesión, que son muchas. Con `-p` elegimos solo las que pide el enunciado:

```bash
root@debian:~# loginctl show-session 19 -p Name -p Timestamp -p RemoteHost -p Service -p IdleHint -p IdleSinceHint
Name=operador
Timestamp=mar 2026-11-03 10:15:02 CET
RemoteHost=192.168.100.10
Service=sshd
IdleHint=no
IdleSinceHint=1793697453104382
```

`loginctl` muestra las propiedades en su propio orden, no en el orden en que se piden.

| Dato que se pide | Propiedad | Valor |
|---|---|---|
| Desde qué IP se ha conectado | `RemoteHost` | `192.168.100.10` |
| Cuánto tiempo lleva conectado | `Timestamp` | Desde las 10:15:02. `session-status` lo da ya calculado: `3min 43s ago`. |
| Tipo de servicio por el que se ha conectado | `Service` | `sshd`, es decir, por SSH |
| Tiempo que lleva sin escribir | `IdleSinceHint` | Momento de la última pulsación de tecla |

`IdleHint` indica si `systemd` considera la sesión inactiva. `IdleSinceHint` indica desde cuándo no hay actividad, pero en microsegundos desde el 1 de enero de 1970. Para leerlo, se quitan los seis últimos dígitos y se convierte con `date`:

```bash
root@debian:~# date -d @1793697453
mar 03 nov 2026 10:17:33 CET
```

`operador` escribió por última vez a las 10:17:33.

> **Nota:** El tiempo sin escribir se ve de forma mucho más cómoda con `w`, en la columna `IDLE` del paso anterior: `1:12` significa que la sesión de `pts/1` lleva 1 minuto y 12 segundos sin actividad. `w` muestra también la IP de origen (`FROM`) y la hora de conexión (`LOGIN@`), así que con una sola orden se obtiene casi todo lo que pide este paso. Lo único que no muestra es el servicio.

### 4. Cerrar las dos conexiones de operador

La sesión 19 la terminamos de forma ordenada y la 21, de forma fulminante:

```bash
root@debian:~# loginctl terminate-session 19
root@debian:~# loginctl kill-session --signal=SIGKILL 21
```

| Orden | Qué hace |
|---|---|
| `terminate-session 19` | Cierra la sesión de forma ordenada. Envía `SIGTERM` a todos sus procesos, que les pide que terminen y les deja cerrar ficheros y guardar lo pendiente, y solo usa `SIGKILL` con los que no hayan terminado pasado un tiempo. |
| `kill-session --signal=SIGKILL 21` | Mata al instante todos los procesos de la sesión. `SIGKILL` no se puede capturar ni ignorar, así que los programas no tienen ninguna opción de terminar ordenadamente. |

En los dos casos también terminan los procesos `sshd-session` de la conexión, así que `operador` ve en sus terminales que el servidor ha cerrado la conexión.

> **Nota:** `kill-session` envía por defecto la señal `SIGTERM`, igual que `terminate-session`. Para el cierre fulminante hay que indicar `--signal=SIGKILL`.

> **Nota:** Para cerrar de una vez todas las sesiones de un usuario, sin buscar sus números, existe `loginctl terminate-user operador`. Su equivalente fulminante es `loginctl kill-user --signal=SIGKILL operador`.

### 5. Comprobar las sesiones y bloquear al usuario

Mostramos las sesiones que quedan y comprobamos que `operador` ya no está conectado:

```bash
root@debian:~# loginctl list-sessions
SESSION  UID USER    SEAT LEADER CLASS   TTY   IDLE SINCE
     14 1000 usuario -    1102   user    pts/0 no   -
     15 1000 usuario -    1108   manager -     no   -

2 sessions listed.
root@debian:~# loginctl user-status operador
Failed to get user: User ID 1001 is not logged in or lingering
```

Quedan dos sesiones, que corresponden a una sola conexión: la de `usuario`. La sesión `manager` de `operador`, la 20, desaparece por sí sola al cerrarse su última conexión.

> **Nota:** Si justo después de cerrar las conexiones todavía aparece la sesión `manager` de `operador`, basta con esperar unos segundos: `systemd` la cierra cuando termina de detener el gestor de servicios de ese usuario.

Bloqueamos al usuario y le cambiamos la shell:

```bash
root@debian:~# passwd -l operador
root@debian:~# passwd -S operador
operador L 2026-11-03 0 99999 7 -1
root@debian:~# chsh -s /usr/sbin/nologin operador
root@debian:~# getent passwd operador
operador:x:1001:1001::/home/operador:/usr/sbin/nologin
```

- **`passwd -l` (*lock*)** bloquea la contraseña: añade un `!` delante del hash en `/etc/shadow`, de modo que ninguna contraseña puede coincidir con él. La `L` de `passwd -S` confirma que está bloqueada.
- **`chsh -s /usr/sbin/nologin`** cambia la shell para que el usuario no pueda abrir una sesión aunque consiga autenticarse.

> **Importante:** `passwd -l` solo bloquea la **contraseña**. Si `operador` tuviera configurada una clave pública de SSH, podría seguir entrando con ella. Por eso se cambia también la shell. Para bloquear la cuenta entera, se puede hacer que caduque con `usermod -e 1 operador`, que fija como fecha de caducidad el 2 de enero de 1970. No conviene usar `chage -E 0`: el valor `0` en ese campo de `/etc/shadow` se puede interpretar como «sin caducidad».

> **Nota:** `usermod -L operador` equivale a `passwd -l`, y `usermod -s /usr/sbin/nologin operador` equivale a `chsh -s`. Para deshacer el bloqueo de la contraseña, se usa `passwd -u operador`.
