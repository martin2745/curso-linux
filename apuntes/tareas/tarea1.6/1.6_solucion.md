# **Solución 1.6: Instalación de software en el sistema: Webmin**

### **Descripción de la tarea**

**Webmin** es una herramienta libre de **administración de sistemas Unix y Linux a través de un navegador web**. Desde una página web se pueden gestionar usuarios y grupos, paquetes, servicios, discos y sistemas de ficheros, la red, el cortafuegos, las tareas programadas o los registros del sistema, además de servidores como Apache, BIND, Samba o MySQL. Para ello, Webmin incluye su propio servidor web (`miniserv.pl`, escrito en Perl), que escucha por HTTPS en el puerto **10000**.

Su importancia se debe a varios motivos:

- **Administración visual y centralizada.** Facilita tareas que por consola exigen recordar muchos comandos y ficheros, y permite gestionar varios servidores desde un mismo panel.
- **Trabaja sobre los ficheros reales del sistema.** Webmin no guarda la configuración en una base de datos propia: cuando se crea un usuario o se cambia un servicio desde la web, modifica los mismos ficheros de `/etc` que se editarían a mano. Por eso es útil para aprender: se puede hacer un cambio en Webmin y buscar después qué ha cambiado en el sistema.
- **Muy extendido.** Es la base de **Virtualmin**, un panel de control para servidores de alojamiento web muy utilizado.
- **Es un objetivo de ataque.** Un panel web que administra el sistema con privilegios de `root` es muy valioso para un atacante. Hay que mantenerlo actualizado, limitar desde dónde se puede acceder a él y no exponerlo nunca directamente a Internet.

Además, la tarea sirve para practicar una forma de instalar software distinta de la habitual: Webmin no está en los repositorios de Debian, así que primero se añade el **repositorio oficial del fabricante** con su clave GPG. A partir de ahí, `apt` lo instala y lo mantiene actualizado como a cualquier otro paquete (documento 27 de los apuntes).

La documentación oficial de Webmin explica su instalación en [webmin.com/download](https://webmin.com/download/) y el resto de su manual en [webmin.com/docs](https://webmin.com/docs/).

La tarea se realiza en un servidor **Debian 13**.

### **Pasos de la tarea**

1. Descarga en `/root` el *script* oficial `webmin-setup-repo.sh`, que configura el repositorio de Webmin.

```bash
root@debian:~# cd /root
root@debian:~# curl -o webmin-setup-repo.sh https://raw.githubusercontent.com/webmin/webmin/master/webmin-setup-repo.sh
  % Total    % Received % Xferd  Average Speed   Time    Time     Time  Current
                                 Dload  Upload   Total   Spent    Left  Speed
100 21890  100 21890    0     0  88742      0 --:--:-- --:--:-- --:--:-- 88987
root@debian:~# ls
webmin-setup-repo.sh
```

_*Nota*_: Las versiones anteriores de esta tarea usaban un *script* llamado `setup-repos.sh`. Sigue existiendo, pero hoy es solo un envoltorio: si se abre, se ve que lo único que hace es descargar y ejecutar `webmin-setup-repo.sh`. Lo correcto es usar directamente este último, que es el que indica la documentación oficial. Antes de ejecutar como `root` un *script* descargado de Internet, conviene leerlo (`less webmin-setup-repo.sh`) para saber qué va a hacer.

2. Ejecuta el *script* para añadir el repositorio de Webmin y su clave GPG, y comprueba qué ficheros ha creado en el sistema.

El *script* está escrito para la shell `sh`, que es como lo ejecuta la documentación oficial. Antes de hacer nada pide confirmación:

```bash
root@debian:~# sh webmin-setup-repo.sh
Setup Webmin Stable repository? (y/N) y
  Downloading Webmin Developers key ..
  .. done
  Installing Webmin Developers key ..
  .. done
  Setting up Webmin Stable repository ..
  .. done
  Cleaning repository metadata ..
  .. done
  Downloading repository metadata ..
  .. done
Webmin and Usermin can be installed with:
  apt-get install --install-recommends webmin usermin
```

El mensaje final sugiere instalar también **Usermin**, una herramienta hermana de Webmin pensada para que los usuarios normales gestionen sus propias cosas (correo, contraseña, ficheros). En esta tarea solo se necesita Webmin.

El *script* ha hecho dos cosas: instalar la **clave GPG** con la que Webmin firma sus paquetes y añadir el **repositorio**, indicando que sus paquetes deben estar firmados con esa clave:

```bash
root@debian:~# ls /usr/share/keyrings/ | grep webmin
debian-webmin-developers.gpg
root@debian:~# cat /etc/apt/sources.list.d/webmin-stable.list
deb [signed-by=/usr/share/keyrings/debian-webmin-developers.gpg] https://download.webmin.com/download/newkey/repository stable contrib
```

La opción `signed-by` hace que `apt` solo acepte paquetes de ese repositorio si están firmados con la clave de Webmin. Así, aunque alguien suplantara el servidor de descargas, sus paquetes serían rechazados.

3. Instala el paquete `webmin` junto con sus paquetes recomendados (`--install-recommends`).

```bash
root@debian:~# apt install webmin --install-recommends
```

`--install-recommends` instala también los paquetes **recomendados** por `webmin`, que no son imprescindibles pero amplían sus funciones. Es la orden que indica la documentación oficial.

_*Nota*_: En las distribuciones de la familia Red Hat, tras ejecutar el mismo *script*, la instalación se hace con `dnf install webmin`.

4. Comprueba que el servicio `webmin` está en marcha y habilitado para arrancar con el sistema.

El paquete deja el servicio arrancado y habilitado, así que basta con comprobarlo:

```bash
root@debian:~# systemctl status webmin
● webmin.service - Webmin server daemon
     Loaded: loaded (/usr/lib/systemd/system/webmin.service; enabled; preset: enabled)
     Active: active (running) since mié 2026-10-08 10:04:43 CEST; 2min 27s ago
    Process: 3048 ExecStart=/usr/share/webmin/miniserv.pl /etc/webmin/miniserv.conf (code=exited, status=0/SUCCESS)
   Main PID: 3049 (miniserv.pl)
      Tasks: 1 (limit: 2303)
     Memory: 67.7M
        CPU: 8.412s
     CGroup: /system.slice/webmin.service
             └─3049 /usr/bin/perl /usr/share/webmin/miniserv.pl /etc/webmin/miniserv.conf
```

`enabled` indica que arrancará con el sistema y `active (running)` que está en marcha. Si no lo estuviera, se arrancaría y habilitaría con `systemctl enable --now webmin` (documento 29 de los apuntes).

5. Comprueba en qué puertos escucha Webmin.

```bash
root@debian:~# ss -tulpn | grep 10000
udp   UNCONN 0      0            0.0.0.0:10000      0.0.0.0:*    users:(("perl",pid=3049,fd=6))
tcp   LISTEN 0      4096         0.0.0.0:10000      0.0.0.0:*    users:(("perl",pid=3049,fd=5))
tcp   LISTEN 0      4096            [::]:10000         [::]:*    users:(("perl",pid=3049,fd=7))
```

Webmin escucha en el puerto **10000/tcp**, en IPv4 y en IPv6, por el que se sirve su interfaz web. El puerto **10000/udp** lo usa para que unos servidores Webmin puedan descubrir a otros en la red. Se usa `ss` en lugar del antiguo `netstat`, que ya no viene instalado (documento 32 de los apuntes).

6. Si el servidor tiene un cortafuegos activo, permite el acceso al puerto 10000 **sin desactivarlo**.

Desactivar el cortafuegos para que funcione un servicio deja el servidor expuesto en todos sus puertos. Lo correcto es abrir solo el que se necesita:

| Cortafuegos | Orden |
|---|---|
| `ufw` (Debian y Ubuntu, documento 44) | `ufw allow 10000/tcp` |
| `nftables` (documento 44) | Añadir `tcp dport 10000 accept` a la cadena `input` de `/etc/nftables.conf` |
| `firewalld` (Red Hat y derivadas) | `firewall-cmd --permanent --add-port=10000/tcp && firewall-cmd --reload` |

En una instalación estándar de Debian 13 no hay ningún cortafuegos activo, así que este paso no es necesario.

7. Accede a Webmin desde el navegador del equipo anfitrión, explica el aviso de seguridad que muestra el navegador e inicia sesión.

Se accede con **`https`**, la IP del servidor y el puerto 10000:

```text
https://IP_DEL_SERVIDOR:10000
```

Si la máquina virtual solo tiene una tarjeta en modo NAT, hay que crear antes en VirtualBox una regla de reenvío de puertos (puerto anfitrión `10000` hacia el puerto invitado `10000`) y entrar con `https://localhost:10000`.

El navegador muestra un aviso de **conexión no segura**. Webmin cifra la conexión con un certificado **autofirmado** que genera al instalarse: la conexión va cifrada, pero ninguna autoridad de certificación reconocida garantiza que el servidor es quien dice ser, y el navegador avisa de ello. En un laboratorio se puede aceptar el riesgo y continuar; en un servidor real se instalaría un certificado válido desde el propio Webmin.

Para iniciar sesión se usa la cuenta **`root`** del servidor o la de un **usuario con permisos de `sudo`**. En los sistemas donde `root` no tiene contraseña, como Ubuntu, se entra con el usuario que se creó durante la instalación.

8. Limita el acceso a Webmin para que solo se pueda entrar desde la red del laboratorio.

Se puede hacer desde la propia interfaz, en **Webmin → Webmin Configuration → IP Access Control**, o directamente en su fichero de configuración, añadiendo la directiva `allow` con las redes permitidas (por ejemplo, `192.168.56.0/24`, la red solo-anfitrión de VirtualBox):

```bash
root@debian:~# echo 'allow=127.0.0.1 192.168.56.0/24' >> /etc/webmin/miniserv.conf
root@debian:~# systemctl restart webmin
```

Desde cualquier otra red, Webmin rechazará la conexión. Junto con mantenerlo actualizado (`apt upgrade` lo actualiza al estar instalado desde su repositorio), es la medida de seguridad más importante.

_*Nota*_: La importancia de mantener Webmin actualizado no es teórica. En 2019 se descubrió que las versiones 1.882 a 1.921 descargadas de SourceForge incluían una **puerta trasera**, introducida por un atacante en el servidor donde se compilaban los paquetes, que permitía ejecutar órdenes como `root` sin contraseña (vulnerabilidad CVE-2019-15107). Los servidores que tenían Webmin expuesto a Internet y sin actualizar fueron atacados de forma masiva.
